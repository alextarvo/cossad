# COSSAD dataset organization

Currently, COSSAD ingests data from three different datasets—Real3D-AD, MulSen, and Anomaly-ShapeNet v.2—and 
converts them into a common format suitable for further processing. We call this the COSSAD dataset format.
This data is used to generate the training set for training the contrastive feature extractor, as well as for inference.
For this documentation, we assume that all data is located in the `./data` folder of the COSSAD
source tree. You may store COSSAD data in a separate folder, and `./data` can be a symlink to that folder.  

The contents of the `./data` folder:
 - `template`: A folder containing point clouds (PCs) for reference template shapes. These are not used
    for training; they are used for inference and/or evaluation only. 
 - `train`: A folder containing PCs of objects that the COSSAD encoder will be trained on and evaluated on.
    Note that we employ 12-fold cross-validation, where validation folds are split according
    to object class name. We train and evaluate COSSAD on different object shapes. Although
    all shapes are stored in the `train` folder, training and validation datasets do not intersect. 
 - Folders that contain patch tuples for encoder training. 

The `train` and `template` folders contain NPZ files produced by the `create_single_dataset.py` script. Each file contains: 
- A point cloud of an object as a NumPy array
- An anomaly mask
- A point cloud label (anomalous or not)
- Anomaly type (if any)
- Names of the files from one of the source datasets (Real3D-AD, MulSen, or Anomaly-ShapeNet) used to generate that NPZ file. 

Patch tuples are generated by the `register_pc_triplets.py`,
`create_supcon_dataset.py`, and `create_contrastive_patch_triplets.py` scripts and are normally stored in folders
named like `supcon_train_r2_2025_11_04_real3dad_norot` or `supcon_train_r2_2025_11_04_shapenet_norot`. The naming
convention is `supcon_train_r<patch radius>_<timestamp>_<dataset name>`. The exact format of the patch tuple file
may change. As of 01/2026, they contain the following:
- Location ID: Uniquely defines a point in a global reference frame where the 
patch was extracted from. In other words, it identifies the patch center. The location ID is the same for all objects of a given class, since they are registered into
the same frame.
- A single NumPy array containing the stacked set of "good" (i.e., anomaly-free) patches and indices of individual patches 
in that stacked array. These are present in FA and WA tuples.
- (Optionally) An array containing a template patch (for WA tuples only).
- (Optionally) An array containing an anomalous patch (for FA tuples only).
COSSAD pipelines expect file names in the following format: `<dataset name>_<object_name>_<patch location id>.npz`, 
e.g., `ashapenet_ashtray0_10001.npz`. Location IDs within (0, 10000) belong to WA patches, and IDs
starting from 10000 are those of FA patches.

Since COSSAD is under active development, naming conventions and file contents may change. We will
do our best to keep this documentation up to date.

# Ready-to-use dataset

You can download our dataset from Cloudflare R2 storage. Download and extract the following files into your ./data
directory:
- https://pub-c3e1c2ecdbd44fc6bf5a8c091a3c3536.r2.dev/template.tar
- https://pub-c3e1c2ecdbd44fc6bf5a8c091a3c3536.r2.dev/train.tar
- https://pub-c3e1c2ecdbd44fc6bf5a8c091a3c3536.r2.dev/supcon_train_r2_2025_11_04_real3dad_norot.tar
- https://pub-c3e1c2ecdbd44fc6bf5a8c091a3c3536.r2.dev/supcon_train_r2_2025_11_04_shapenet_norot.tar

Directories `train` and `template` contain the raw COSSAD dataset; you can use it for validation. 
You can also use this data to regenerate the training set for training the contrastive feature extractor.

Directories `supcon_train_r2_2025_11_04_real3dad_norot` and `supcon_train_r2_2025_11_04_shapenet_norot` contain
the ready-to-use training set for training the contrastive feature extractor. See [Training instructions](training.md).
